# Loading and search responsiveness

## Baseline

Production Electron build, fresh isolated QA profile, 865 px viewport. The first
discovery heading sat at y=1284, below the visible page, but all four discovery
queries were submitted at 3.94 seconds without scrolling. The loaded page had
122 anime links. The observed first contentful paint was 1715 ms.

The tablet debug app's observed cold Activity launch was 2360 ms. These single
launch timings are recorded for context; they are not a controlled speed claim.

## Changes

- Desktop discovery rows reuse cached content immediately and defer uncached
  catalogue requests until within 240 px of the viewport. Light placeholders
  reserve each row's space. Intersection checks begin after core Home loading
  settles (with the existing eight-second fallback), preventing the initial
  empty layout from marking every lower row visible.
- Desktop AniList deadlines now include successful/error response bodies, and
  a timeout releases the caller even if its transport ignores cancellation.
  Late responses and rate-limit bodies are closed. Existing serial request
  spacing, retry limits and rate-limit handling remain in use.
- Android AniList calls stay cancellable through body reading. Leaving a
  screen or replacing a search cancels its socket and releases the serial
  request lock; cancellation is not retried as an ordinary network error.
- Native search effects propagate cancellation. Browse results load before
  the optional Top rated sidebar, which is omitted on narrow screens.

## Validation

The final production Electron QA build made **zero** discovery queries before
scrolling, compared with four in the baseline. Anime links before scrolling
fell from 122 to 50, deferring 72 discovery cards. Scrolling to Top Airing
loaded that row, Most Popular, and the nearby Top Movies row (18 cards each);
Highest Rated remained deferred below them. The final sample's first contentful
paint was 1599 ms. A run during concurrent build/test load measured 11389 ms;
these launch timings are not used as an overall speedup claim.

Desktop search returned Cowboy Bebop and its related titles through the updated
transport. On the Tab S7 FE, typing cow → cowboy → cowboy Bebop produced the
correct preview with the software keyboard visible; Search then opened the
correct four browse results and Top rated sidebar. The debug APK was updated in
place over the tablet's active wireless connection. The test app was stopped
afterward and the previous Settings activity resumed.

Native tests and debug APK assembly succeeded: 430 tests, three skipped, zero
failures or errors. Four new transport tests cover success/closure, cancellation
before headers, cancellation during body consumption plus serial-lock release,
and transport/body failures. Desktop deadline regressions cover stalled success
and error bodies, abort-ignoring fetches, late response disposal, rate-limit
headers, and unchanged request/response data.

The production desktop build succeeded and all 461 Node tests passed with
--test-concurrency=1 and the test apps closed. Earlier concurrent checks hit
timing limits in download fixtures; the assertions remain unchanged. The final
type check passed. No commit, push, or release has been made.
